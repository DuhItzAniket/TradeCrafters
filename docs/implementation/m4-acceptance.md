## Explicit operating limits

- This is a personal **synthetic** demo. Ten fictional listings across six regions and 2,889 dated MIC reference records are not verified real-exchange integrations. Real feeds, live liquidity and real orders/funds remain disabled; M5/#7 and worldwide inventory #9/M7 stay open.
- M3/#5 remains open for the owner-deferred 3–5 real student walkthroughs. Engineering checks cannot substitute for those observations.
- Free hosting can idle shut down or change placement, and has no SLA/HA promise. Capacity samples are short and small; registration/storage need owner review before a class/public campaign. Production password fallback and arbitrary AWS ingress trust are not enabled.
- Provider disaster-recovery backups are automated; the portable weekly checkpoint is a documented operator task. No unattended offsite scheduler, provider PITR/failover, fresh-machine cloud rebuild or guaranteed RPO/RTO was demonstrated. The isolated portable restore is the supported tested application recovery path.
- The independently held authenticated archive protects historical audit comparison; the live database is not tamper-proof. Manual account closure needs independent identity verification and a reviewed scoped case; no general erase endpoint is claimed. Restore must reapply completed deletions before reopening.
- Smoke sampling and fixed-scope diagnostics support failure review. Notification preferences/delivery are owner/provider controlled and no delivery SLA is claimed. GitHub schedules can be delayed or disabled for inactivity.

The [required verification matrix](../ROADMAP.md#required-verification-matrix) is covered by M1/M2 integrity tests, the workbench's mobile/keyboard/failure checks and the hosted M4 evidence above. Controlled provider faults and synthetic per-listing/FX unavailability are distinguished from future captured real-provider outage tests. No release gate is satisfied by enabling an unlicensed feed or weakening authentication.
